# Oversight for AI Agents

AI agents now run SQL, send email and pay invoices. Keeping a human in the loop sounds safe, but a person who is asked to approve something fifty times a day stops reading after the tenth.

This project decides who should check each action an agent wants to take. Low risk actions just run. Medium risk actions go to a safety model. High risk actions go to a person, as long as that person still has attention to spare. Critical actions always go to a person, and if nobody is around they wait.

Every decision is written to a log together with the reasons behind it.

## How it decides

Each tool call gets a risk score from four things: what kind of action it is, whether it can be undone, how far the damage could reach, and how sensitive the data is. The weights live in `policies/default.yaml`. The file `policies/tools.yaml` says how risky each tool normally is and which parameters make it riskier (a `SELECT` is fine, a `DROP TABLE` is not).

The router also keeps track of the human: are they around, and how many times have they been interrupted in the last hour. When the budget is used up, high risk actions go to the safety model instead, which has to be more confident before it approves anything. Anything it is unsure about waits for the human.

The router itself is plain code with no model calls, so the same input always gives the same decision.

## Try it

You need Python 3.11 and uv.

```
uv sync
uv run pytest
uv run python demo_cli.py
```

To reproduce every number and the chart above (takes about half a minute and costs nothing):

```
uv run python scripts/run_experiments.py
uv run python scripts/make_report.py
```

## Using it with Claude Code

The project includes a hook that sits in front of Claude Code's own tool calls. Claude Code's permission prompt plays the role of the human, and the attention budget decides how often it asks. See `examples/claude_code_settings.json` for the setup. By default the hook never approves anything by itself. It only blocks or asks.

`examples/agent_loop.py` shows a Claude agent where every tool call goes through the same checks, working on a fake company with made up data.

## Using a real model as the safety model

The committed results use a simple rule based reviewer. You can swap in Claude by running the experiment script with `reviewer anthropic` (see the top of `scripts/run_experiments.py`). Spending is capped by the `MAX_SPEND_USD` setting and every answer is cached, so running it twice costs nothing extra.

## What to keep in mind

All data here is made up, and the human is simulated. The numbers compare strategies with each other. They do not predict how any real system will behave.

The rule based reviewer misses most of the subtle harmful actions. If a harmful action looks harmless to the tool registry, no reviewer ever sees it.
